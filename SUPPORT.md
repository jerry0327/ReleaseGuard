# Support

ReleaseGuard is maintained on a best-effort basis.

## Supported line

The latest commit on `main` and the latest published release are the supported development line before 1.0. Security fixes are not guaranteed to be backported to older pre-1.0 versions.

## Where to ask

- Reproducible bugs: GitHub bug-report template.
- Feature proposals: GitHub feature-request template.
- Security vulnerabilities: the private process in [SECURITY.md](SECURITY.md).

Do not include secrets, registry credentials, private package coordinates, or unpatched exploit details in public issues.

## Useful bug reports

Include the ReleaseGuard version or commit, Python/npm version where applicable, operating system, command or workflow excerpt, sanitized configuration, exact finding IDs, expected behavior, and a minimal non-sensitive reproduction.

## Scope

Support covers ReleaseGuard's documented CLI, Actions, policy files, evidence schemas, and public-registry verification boundaries. It does not include general GitHub, npm, Sigstore, PyPI, Cargo, cloud-runner, or registry administration support.

## Response expectations

There is no contractual response-time commitment. Security reports are prioritized over ordinary feature requests. Repeated requests without a reproduction may be closed until actionable evidence is available.
